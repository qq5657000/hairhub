# HairHub V1.0 数据库实施规范

> 适用范围：Laravel 10 + Dcat Admin + MySQL 8.0+

## 1. 基础约定

- 存储引擎：`InnoDB`
- 字符集：`utf8mb4`
- 排序规则：项目统一，不在单表中随意指定
- 表名：小写、下划线、复数形式
- 字段名：小写、下划线，禁止缩写和拼音
- 主键：`id BIGINT UNSIGNED AUTO_INCREMENT`
- 默认使用 Laravel Migration 管理结构变更

## 2. 字段规范

- 关联字段：`xxx_id BIGINT UNSIGNED`
- 状态字段：`TINYINT UNSIGNED`
- 排序字段：`sort INT UNSIGNED DEFAULT 0`
- 金额字段：`DECIMAL`，禁止使用 `FLOAT`
- 时间字段：`created_at`、`updated_at`
- 软删除字段：仅业务主表按需增加 `deleted_at`
- 长文本使用 `TEXT` 或 `LONGTEXT`
- JSON 仅保存低频、弱查询、结构可能变化的数据

## 3. 关联与外键

- 默认不创建数据库物理外键
- 通过 Eloquent 维护逻辑关联
- 所有关联字段必须建立索引
- 删除主数据时不得隐式物理删除重要业务记录

## 4. 索引规范

必须评估：

- 唯一索引：`slug`、业务编号等
- 单列索引：高频筛选、关联字段
- 联合索引：按实际查询条件和排序设计
- 禁止重复索引、无效索引和机械式全字段索引

索引命名：

```text
uk_字段
idx_字段
idx_字段1_字段2
```

## 5. 状态与枚举

- 数据库存整数状态值
- PHP 使用 Enum 或常量统一维护
- 禁止在业务代码中散落魔法数字和字符串状态
- 不同业务含义应使用明确字段，如 `publish_status`、`task_status`

## 6. 软删除原则

建议使用软删除：

- 发型、发色、文章、视频、专题等可恢复业务内容

通常不使用软删除：

- 关联表
- AI 任务日志
- 同步日志
- 系统配置变更记录

## 7. Migration 要求

- 必须实现 `up()` 和 `down()`
- 已上线 Migration 禁止直接修改
- 新增变更必须创建新的 Migration
- 建表顺序按依赖关系执行
- 禁止在 Migration 中写复杂业务逻辑
