# HairHub V1.0 系统基础与任务支撑模块数据库详细设计

> Version: 1.0.0  
> 适用项目：HairHub 发型中心  
> 技术栈：Laravel 10 + Dcat Admin + MySQL 8.0+ + Redis  
> 文档路径：`/docs/v1.0/database/08-系统基础与任务支撑模块.md`

---

# 一、模块目标

本模块用于明确 HairHub 项目中的 Laravel 基础设施、队列支撑、失败任务、批处理、缓存、Session 和 Dcat Admin 系统表边界。

主要目标：

- 明确队列使用 Redis，不使用数据库作为主队列
- 明确哪些 Laravel 系统表需要创建
- 明确哪些表不需要创建
- 支持 AI 任务、微信同步、缩略图、媒体清理等异步任务
- 支持失败任务排查
- 支持批量任务状态追踪
- 避免 Cursor 重复生成 Laravel 或 Dcat 系统表
- 避免业务表与框架表职责混淆

---

# 二、基础架构结论

HairHub V1.0 推荐配置：

```env
QUEUE_CONNECTION=redis
CACHE_STORE=redis
SESSION_DRIVER=redis
```

因此：

```text
队列：Redis
缓存：Redis
Session：Redis
```

MySQL 只用于：

- 业务数据
- 失败任务记录
- 批处理任务记录
- Dcat Admin 系统数据
- 必要的审计与运维数据

# 三、V1.0 系统表清单

建议创建：

```text
failed_jobs
job_batches
```

通常不创建：

```text
jobs
cache
cache_locks
sessions
```

Dcat Admin 已有或由框架安装生成的系统表：

```text
admin_users
admin_roles
admin_permissions
admin_menu
admin_role_users
admin_role_permissions
admin_role_menu
admin_settings
admin_extensions
admin_extension_histories
```

具体表名以当前 dcat-plus 项目实际 Migration 为准。

原则：

- 不重复创建 Dcat Admin 系统表
- 不随意修改 Dcat Admin 核心表结构
- 不将业务字段塞入管理员系统表
- 业务权限通过 Dcat Permission 和业务代码控制

# 四、为什么不使用数据库队列

HairHub 存在较多异步任务：

- AI 换发型
- AI 换发色
- 微信公众号同步
- 缩略图生成
- 视频封面提取
- 媒体过期清理
- 文件缺失检测
- SEO 缓存刷新
- 批量内容导入

Redis Queue 更适合：

- 更高吞吐
- 更低延迟
- Worker 调度
- 队列分组
- Horizon 监控
- 失败重试
- 延迟任务
- 优先级队列

因此 V1.0 不使用：

```env
QUEUE_CONNECTION=database
```

也不创建：

```text
jobs
```

# 五、failed_jobs 失败任务表

## 5.1 表用途

记录 Laravel Queue 执行失败的 Job，用于：

- 排查失败原因
- 人工重试
- 查看异常堆栈
- 统计失败任务
- 运维清理

## 5.2 Laravel 标准字段

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT UNSIGNED | 主键 |
| uuid | VARCHAR(255) | 失败任务唯一标识 |
| connection | TEXT | 队列连接 |
| queue | TEXT | 队列名称 |
| payload | LONGTEXT | Job Payload |
| exception | LONGTEXT | 异常信息 |
| failed_at | TIMESTAMP | 失败时间 |

## 5.3 建表 SQL 参考

```sql
CREATE TABLE `failed_jobs` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `uuid` VARCHAR(255) NOT NULL,
    `connection` TEXT NOT NULL,
    `queue` TEXT NOT NULL,
    `payload` LONGTEXT NOT NULL,
    `exception` LONGTEXT NOT NULL,
    `failed_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_uuid` (`uuid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5.4 使用规则

- 使用 Laravel 官方 Migration。
- 不自行扩展业务字段。
- 业务任务关联应通过 Job Payload、task_no 或业务日志完成。
- 不在后台直接编辑失败任务。
- 重试使用 Laravel 官方命令。
- 定期清理长期无用记录。

## 5.5 常用命令

```bash
php artisan queue:failed
php artisan queue:retry all
php artisan queue:retry <id>
php artisan queue:forget <id>
php artisan queue:flush
```

生产环境禁止随意执行：

```bash
php artisan queue:flush
```

执行前必须确认失败任务是否需要保留。

# 六、job_batches 批处理任务表

## 6.1 表用途

支持 Laravel Bus Batch，用于：

- 批量图片处理
- 批量缩略图生成
- 批量内容同步
- 批量媒体检测
- 批量数据导入
- 批量 AI 任务

## 6.2 Laravel 标准字段

| 字段 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(255) | Batch ID |
| name | VARCHAR(255) | 批处理名称 |
| total_jobs | INT | 总任务数 |
| pending_jobs | INT | 待执行数 |
| failed_jobs | INT | 失败数 |
| failed_job_ids | LONGTEXT | 失败 Job ID |
| options | MEDIUMTEXT | Batch 配置 |
| cancelled_at | INT | 取消时间戳 |
| created_at | INT | 创建时间戳 |
| finished_at | INT | 完成时间戳 |

## 6.3 建表 SQL 参考

```sql
CREATE TABLE `job_batches` (
    `id` VARCHAR(255) NOT NULL,
    `name` VARCHAR(255) NOT NULL,
    `total_jobs` INT NOT NULL,
    `pending_jobs` INT NOT NULL,
    `failed_jobs` INT NOT NULL,
    `failed_job_ids` LONGTEXT NOT NULL,
    `options` MEDIUMTEXT NULL,
    `cancelled_at` INT NULL,
    `created_at` INT NOT NULL,
    `finished_at` INT NULL,
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6.4 使用规则

- 使用 Laravel 官方 Migration。
- 不修改字段类型。
- 不增加业务字段。
- 业务关联通过 Batch name 或 options 保存。
- 批处理结果不替代业务任务表。
- AI 任务仍以 `ai_tasks` 为主数据来源。

# 七、不创建的 Laravel 表

## 7.1 jobs

不创建原因：

```text
QUEUE_CONNECTION=redis
```

Redis 保存待执行队列数据。

只有改为数据库队列时才需要：

```bash
php artisan queue:table
```

V1.0 禁止 Cursor 默认生成 `jobs` 表。

## 7.2 cache 和 cache_locks

不创建原因：

```text
CACHE_STORE=redis
```

只有使用数据库缓存时才需要：

```bash
php artisan cache:table
```

## 7.3 sessions

不创建原因：

```text
SESSION_DRIVER=redis
```

只有使用数据库 Session 时才需要：

```bash
php artisan session:table
```

# 八、Redis 数据职责

Redis 用于：

- Laravel Queue
- Laravel Cache
- Laravel Session
- 分布式锁
- 限流
- 临时验证码
- AI 任务状态辅助缓存
- 首页和 SEO 缓存
- 防重复提交

Redis 不作为：

- 永久业务数据库
- AI 任务唯一状态来源
- 媒体元数据主存储
- 订单和计费主存储
- 内容主存储

重要业务状态必须最终写入 MySQL。

# 九、Redis Key 命名

建议统一前缀：

```text
hairhub:
```

示例：

```text
hairhub:queue:ai
hairhub:lock:ai_task:{id}
hairhub:cache:home_blocks:{locale}
hairhub:cache:seo:{locale}:{type}:{id}
hairhub:cache:setting:{key}
hairhub:session:{session_id}
hairhub:rate_limit:api:{ip}
```

规则：

- 小写
- 使用冒号分层
- 不使用中文
- Key 必须有明确业务前缀
- 临时 Key 必须设置 TTL
- 锁必须设置过期时间
- 禁止永久保存大 JSON

# 十、队列划分建议

V1.0 建议队列：

```text
default
ai
media
wechat
maintenance
```

用途：

```text
default      普通异步任务
ai           AI 换发型、换发色、脸型分析
media        缩略图、视频封面、媒体检测
wechat       公众号同步与发布
maintenance  清理、修复、归档任务
```

建议优先级：

```text
ai-high
ai
default
media
wechat
maintenance
```

是否启用多优先级队列，应根据 Worker 配置决定。

# 十一、Queue Job 规范

每个 Job 必须：

- 单一职责
- 支持重试
- 支持超时
- 支持失败处理
- 支持幂等
- 不依赖请求上下文
- 不保存超大对象
- 不直接序列化完整 Model 集合
- 只传必要 ID 或业务编号

示例：

```php
final class ExecuteAiTaskJob implements ShouldQueue
{
    public int $tries = 3;

    public int $timeout = 300;

    public function __construct(
        public readonly int $taskId
    ) {
    }
}
```

禁止：

```php
new ExecuteAiTaskJob($hugeModelCollection);
```

---

# 十二、Job 重试与超时

建议：

## 12.1 AI 任务

```text
tries = 3
timeout = 300～900 秒
backoff = [30, 120, 300]
```

具体按模型执行时间调整。

## 12.2 媒体任务

```text
tries = 3
timeout = 120 秒
backoff = [10, 60, 180]
```

## 12.3 微信同步

```text
tries = 5
timeout = 60 秒
backoff = [30, 60, 180, 600]
```

规则：

- 不可重试错误应主动 fail。
- 参数错误不得反复重试。
- 内容安全拒绝不得自动重试。
- 网络和限流错误可重试。
- 重试次数必须与业务表状态一致。

---

# 十三、任务幂等与锁

## 13.1 幂等

适用场景：

- AI 任务重复提交
- 微信文章重复同步
- 缩略图重复生成
- 媒体重复清理
- 批量导入重复执行

实现方式：

- MySQL 唯一索引
- Redis Lock
- 业务状态判断
- idempotency_key

原则：

> Redis 锁负责并发控制，MySQL 唯一索引负责最终一致性。

## 13.2 分布式锁

示例：

```php
Cache::lock("hairhub:lock:ai_task:{$taskId}", 600)
    ->block(5, function () use ($taskId) {
        // 执行任务
    });
```

要求：

- 锁必须有 TTL。
- 锁范围必须最小化。
- 不在锁内执行无关操作。
- 超时后必须可恢复。
- 不能只依赖锁，不做状态校验。

# 十四、Laravel Horizon

V1.0 建议安装或启用 Laravel Horizon，用于：

- Redis Queue 监控
- Worker 状态
- 吞吐量
- 任务运行时间
- 失败任务
- 队列积压
- 标签分类

如项目暂未安装 Horizon，可先使用：

```bash
php artisan queue:work redis
```

后续任务量增加再启用 Horizon。

Horizon 标签建议：

```text
ai-task:{task_no}
provider:{provider}
type:{type}
media:{media_id}
wechat-article:{article_id}
```

# 十五、Supervisor 进程建议

生产环境应使用 Supervisor 或 systemd 管理 Worker。

示例：

```ini
[program:hairhub-ai-worker]
command=php /data/hairhub/artisan queue:work redis --queue=ai-high,ai --sleep=1 --tries=3 --timeout=600
directory=/data/hairhub
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
numprocs=2
redirect_stderr=true
stdout_logfile=/data/hairhub/storage/logs/ai-worker.log
```

注意：

- 部署新代码后执行 `queue:restart`。
- Worker 用户必须有 storage 权限。
- 不使用 root 运行 Worker。
- 不同队列建议独立进程。

# 十六、计划任务 Scheduler

建议配置：

```bash
* * * * * php /data/hairhub/artisan schedule:run >> /dev/null 2>&1
```

V1.0 定时任务：

```text
清理过期媒体
检测丢失媒体
清理失败任务
刷新首页缓存
清理过期锁
归档历史 AI 任务
检查队列积压
```

Laravel 任务示例：

```php
Schedule::command('media:cleanup-expired')
    ->hourly()
    ->withoutOverlapping();

Schedule::command('media:detect-missing')
    ->dailyAt('03:00')
    ->withoutOverlapping();

Schedule::command('queue:prune-failed --hours=168')
    ->daily();
```

# 十七、failed_jobs 清理策略

建议保留：

```text
7～30 天
```

命令：

```bash
php artisan queue:prune-failed --hours=168
```

规则：

- 关键故障先导出或记录。
- 清理前确认无待处理人工重试。
- 不无限保留异常堆栈。
- Payload 中可能包含业务参数，需注意隐私。

---

# 十八、job_batches 清理策略

Laravel Batch 记录可定期清理。

建议保留：

```text
7～30 天
```

可使用官方 prune 能力或自定义命令。

规则：

- 业务完成状态必须已写入业务表。
- 不依赖 job_batches 作为长期业务历史。
- 清理前确认无进行中的 Batch。

## 19.1 不修改核心表

```text

admin_roles
admin_permissions
```

- dcat-plus 官方升级要求

- Dcat Menu
- Dcat Permission
- Route Middleware

实现。

# 二十一、部署与迁移顺序

建议：

```text
1. 检查 Dcat Admin 已有 Migration
2. 创建 failed_jobs
3. 创建 job_batches
4. 配置 Redis
5. 配置队列
6. 配置 Session 和 Cache
7. 配置 Supervisor / systemd
8. 配置 Scheduler
9. 启动 Worker
10. 测试失败重试和任务恢复
```

Laravel 命令：

```bash
php artisan queue:failed-table
php artisan queue:batches-table
php artisan migrate
```

注意：

- 如果项目已有对应 Migration，不要重复生成。
- 执行前检查 migration 文件和数据库表。

```env
QUEUE_CONNECTION=redis
CACHE_STORE=redis
SESSION_DRIVER=redis

REDIS_CLIENT=phpredis
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
```

实际变量名以 Laravel 配置文件为准。

要求：

- 生产环境 Redis 必须设置认证或内网隔离。
- Redis 不对公网开放。
- retry_after 必须大于最长 Job 执行时间。
- Worker timeout 应小于 retry_after。

# 二十三、监控指标

建议监控：

- 各队列长度
- Worker 数量
- 任务平均等待时间
- 任务平均执行时间
- 每小时失败任务数
- 重试次数
- Redis 内存
- Redis 连接数
- Redis Key 数量
- 长时间 processing 的 AI 任务
- 未完成 Batch 数量

告警示例：

```text
AI 队列积压超过 100
失败任务 10 分钟内超过 20
Worker 数量为 0
Redis 内存超过 80%
AI 任务 processing 超过 30 分钟
```

# 二十五、Cursor 开发约束

Cursor 开发本模块时必须：

1. 阅读本文档和 `.cursor/rules`。
2. 检查项目现有 Migration 和 Dcat 系统表。
3. 队列使用 Redis，不创建 `jobs` 表。
4. 缓存使用 Redis，不创建 `cache`、`cache_locks`。
5. Session 使用 Redis，不创建 `sessions`。
6. 只在缺失时创建 `failed_jobs` 和 `job_batches`。
7. 使用 Laravel 官方 Migration 结构。
8. 不修改 Dcat Admin 核心表。
9. 不向 admin_users 添加业务字段。
10. Job 必须支持幂等、重试、超时和失败处理。
11. Job 只传必要 ID，不序列化大对象。
12. 分布式锁必须有 TTL。
13. Worker timeout 必须小于 retry_after。
14. 业务状态必须写入业务表。
15. 不记录敏感凭证。
16. 不修改无关模块。
17. 完成后输出文件清单、命令和风险点。

# 二十七、设计结论

HairHub V1.0 系统基础与任务支撑模块采用：

```text
Redis Queue
+
Redis Cache
+
Redis Session
+
failed_jobs
+
job_batches
+
Supervisor / systemd
+
Laravel Scheduler
```

该方案能够满足：

- AI 任务异步执行
- 微信同步
- 媒体处理
- 批量任务
- 失败重试
- 队列监控
- 分布式锁
- 缓存与 Session
- 生产环境 Worker 管理

V1.0 不使用数据库队列，不创建 jobs、cache、cache_locks 和 sessions 表，并严格保持 Dcat Admin 系统表与业务表分离。
