# 一、AI 模块定位

HairHub V1.0 的 AI 模块定位：

> AI 是 HairHub 的流量入口和体验工具，不是 HairHub 的核心推理系统。

HairHub 本身不训练模型、不运行模型、不直接管理 GPU 推理过程。

HairHub 只负责：

```text
上传图片

创建任务

调用 AI Provider

保存任务记录

保存生成结果

返回结果给前端

后台排查任务
```

当前 AI 推理能力由独立 4090D 显卡主机提供。

---

# 二、当前 AI 服务现状

V1.0 当前可用 AI 能力：

```text
HairFastGAN

独立 4090D GPU 服务器

通过 HTTP API 调用
```

HairHub 与 AI 服务器之间通过 API 通信。

架构：

```text
HairHub Web服务器

↓

AiService

↓

HairFastGanProvider

↓

4090D AI服务器

↓

HairFastGAN 推理服务
```

---

# 三、AI 设计目标

AI 模块设计目标：

```text
轻量

稳定

可替换

可追踪

可扩展
```

具体包括：

* 不把 AI 模型代码放进 HairHub 项目
* 不让 Controller 直接调用 AI API
* 所有 AI 调用必须记录任务
* 所有 AI 失败必须可排查
* 未来可接入 OpenAI、Flux、ComfyUI 等模型
* 前端只关心任务状态和结果，不关心具体模型

# 六、核心类职责

## 6.1 AiService

`AiService` 是业务入口。

负责：

```text
接收业务参数

创建 ai_tasks

调用 MediaService 保存图片

读取目标发型/发色

组装 request_params

选择 Provider

调用 Provider

保存结果图片

更新任务状态

返回任务结果
```

Controller 只调用 AiService。

---

## 6.2 AiProviderInterface

定义所有 AI Provider 的统一能力。

建议方法：

```php
public function generate(array $params): array;
```

返回统一结构：

```php
[
    'success' => true,
    'result_url' => '',
    'raw_response' => [],
    'error_message' => null,
]
```

---

## 6.3 HairFastGanProvider

负责对接当前 HairFastGAN API。

职责：

```text
读取API地址

读取超时时间

组装HTTP请求

发送请求

解析响应

处理异常

返回统一结果格式
```

禁止在 Controller 中直接写 HairFastGAN 请求代码。

# 十、任务状态

AI 任务状态：

```text
pending

processing

success

failed
```

说明：

| 状态         | 说明         |
| ---------- | ---------- |
| pending    | 任务已创建，尚未开始 |
| processing | AI正在处理     |
| success    | 生成成功       |
| failed     | 生成失败       |

# 十五、同步与异步策略

## 15.1 V1.0 简化方案

V1.0 可以先采用同步调用：

```text
前端提交

↓

后端调用AI API

↓

等待结果

↓

返回任务结果
```

适合：

```text
AI生成耗时较短

并发量较低

快速上线
```

---

## 15.2 推荐更稳方案

如果生成耗时较长，建议改为：

```text
前端提交任务

↓

后端立即返回 task_no

↓

队列异步调用AI

↓

前端轮询任务状态

↓

成功后展示结果
```

推荐前端轮询：

```text
GET /api/v1/ai/tasks/{task_no}
```

---

## 15.3 V1.0 建议

建议采用：

> 任务表 + 可轮询状态

即使后端第一版同步调用，也应保留任务记录。

这样后续切换队列异步时，前端和数据库不需要大改。





# 十九、用户图片隐私策略

V1.0 不开发用户登录。

因此 AI 上传图片默认视为临时资源。

建议：

```text
不公开收录

不进入 sitemap

不展示在公共图库

不用于SEO页面

不作为推荐内容
```

robots.txt 中应禁止抓取：

```text
/storage/uploads/user/

/storage/uploads/ai/
```

# 二十三、超时策略



# 二十四、频率限制

V1.0 没有用户登录。

建议至少按 IP 做简单限制。

例如：

```text

同一IP每天最多N次
```

避免：

```text
恶意刷接口

GPU资源被耗尽

服务器费用失控
```

# 三十、AI 模块总结

HairHub V1.0 AI 模块核心原则：

```text
HairHub 不做模型

↓

HairHub 调用模型

↓

AI 服务通过 Provider 解耦

↓

所有调用必须记录任务

↓

所有图片统一进入 Media

↓

所有失败必须可排查

↓

未来可替换模型
```

最终目标：

> 用最轻量、稳定、可扩展的方式，把 AI 换发型和 AI 换发色作为 HairHub 的流量入口，而不是把整个项目变成沉重的 AI 平台。
