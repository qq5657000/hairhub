# HairHub V1.0 内容模块 MySQL 表结构详细设计

> Version: 1.0.0  
> 适用项目：HairHub 发型中心  
> 技术栈：Laravel 10 + Dcat Admin + MySQL 8.0+  
> 文档路径：`/docs/v1.0/database/03-内容模块.md`

---

# 一、模块目标

内容模块用于管理 HairHub 的核心内容资产，包括：

- 文章分类
- 网站文章
- 视频教程
- 专题内容
- 微信公众号文章同步记录
- 内容发布状态
- 内容封面及 SEO 信息

V1.0 涉及以下数据表：

```text
article_categories
articles
videos
topics
wechat_articles
```

---

# 二、数据关系

```text
article_categories
        │
        │ 1:N
        ▼
     articles
        │
        │ 1:0..1
        ▼
 wechat_articles


media_files
   ▲     ▲     ▲
   │     │     │
articles videos topics
```

关系说明：

- 一个文章分类可以包含多篇文章。
- 一篇文章只能归属一个主分类。
- 一篇文章最多对应一条微信公众号同步记录。
- 文章、视频和专题的封面通过 `media_files` 逻辑关联。
- 不创建数据库物理外键。

# 三、统一设计约定

## 3.1 基础规范

- 存储引擎：`InnoDB`
- 字符集：`utf8mb4`
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 不创建数据库物理外键
- 所有逻辑关联字段必须建立索引
- 状态字段使用 `TINYINT UNSIGNED`
- 状态值由 PHP Enum 统一管理
- 文章、视频、专题和分类使用软删除
- 微信同步记录不使用软删除
- 内容正文使用 `LONGTEXT`
- 网站内容与公众号内容分开保存

## 3.2 排序规则

后台默认排序：

```text
sort DESC, id DESC
```

前台内容列表默认排序：

```text
published_at DESC, id DESC
```

说明：

- `sort` 用于运营置顶。
- `published_at` 用于内容发布时间排序。
- `id` 保证相同时间或排序值下结果稳定。

## 3.3 通用状态

建议统一内容状态：

```text
0 = draft
1 = published
2 = disabled
```

对应 PHP Enum：

```php
enum ContentStatus: int
{
    case Draft = 0;
    case Published = 1;
    case Disabled = 2;
}
```

说明：

- `draft`：草稿。
- `published`：已发布。
- `disabled`：已下架或禁用。
- 不再单独使用简单的 0/1 状态表示所有内容生命周期。

# 四、article_categories 文章分类表

## 4.1 表用途

管理文章分类，支持一级和二级分类。

示例：

```text
男生发型
├── 男生剪发
├── 男生烫发
└── 男生打理

女生发型
├── 女生短发
├── 女生长发
└── 女生染发

儿童发型
├── 男童发型
└── 女童发型
```

V1.0 建议最多支持两级分类。

## 4.2 字段结构

| 字段 | 类型 | 是否为空 | 默认值 | 说明 |
|---|---|---:|---:|---|
| id | BIGINT UNSIGNED | 否 | 自增 | 主键 |
| parent_id | BIGINT UNSIGNED | 否 | 0 | 父分类 ID，0 表示顶级分类 |
| name | VARCHAR(100) | 否 | 无 | 分类名称 |
| name_en | VARCHAR(150) | 否 | `''` | 英文名称预留 |
| slug | VARCHAR(150) | 否 | 无 | SEO URL 标识 |
| description | VARCHAR(500) | 是 | NULL | 分类简介 |
| cover_media_id | BIGINT UNSIGNED | 否 | 0 | 分类封面媒体 ID |
| status | TINYINT UNSIGNED | 否 | 1 | 状态 |
| sort | INT UNSIGNED | 否 | 0 | 排序值 |
| created_at | TIMESTAMP | 是 | NULL | 创建时间 |
| updated_at | TIMESTAMP | 是 | NULL | 更新时间 |
| deleted_at | TIMESTAMP | 是 | NULL | 软删除时间 |

## 4.3 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_slug` (`slug`),
KEY `idx_parent_status_sort` (`parent_id`, `status`, `sort`),
KEY `idx_cover_media_id` (`cover_media_id`),
KEY `idx_deleted_at` (`deleted_at`)
```

## 4.4 建表 SQL 参考

```sql
CREATE TABLE `article_categories` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `parent_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `name` VARCHAR(100) NOT NULL,
    `name_en` VARCHAR(150) NOT NULL DEFAULT '',
    `slug` VARCHAR(150) NOT NULL,
    `description` VARCHAR(500) NULL,
    `cover_media_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `status` TINYINT UNSIGNED NOT NULL DEFAULT 1,
    `sort` INT UNSIGNED NOT NULL DEFAULT 0,
    `created_at` TIMESTAMP NULL DEFAULT NULL,
    `updated_at` TIMESTAMP NULL DEFAULT NULL,
    `deleted_at` TIMESTAMP NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_slug` (`slug`),
    KEY `idx_parent_status_sort` (`parent_id`, `status`, `sort`),
    KEY `idx_cover_media_id` (`cover_media_id`),
    KEY `idx_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 4.5 业务规则

- 顶级分类的 `parent_id = 0`。
- 不允许父级分类指向自身。
- V1.0 不允许超过两级分类。
- 已被文章使用的分类不得直接物理删除。
- 删除分类前必须检查子分类和文章引用。
- `slug` 只允许小写字母、数字和短横线。

| published_at | TIMESTAMP | 是 | NULL | 发布时间 |
| seo_title | VARCHAR(255) | 否 | `''` | SEO 标题 |
| seo_description | VARCHAR(500) | 否 | `''` | SEO 描述 |
| created_at | TIMESTAMP | 是 | NULL | 创建时间 |
| updated_at | TIMESTAMP | 是 | NULL | 更新时间 |
| deleted_at | TIMESTAMP | 是 | NULL | 软删除时间 |

## 5.3 字段说明

### content_format

```text
1 = markdown
2 = html
```

V1.0 建议网站正文默认使用 Markdown，最终展示时转换为 HTML。

### wechat_content

公众号正文单独保存 HTML 内容。

原因：

- 公众号排版与网站不同。
- 公众号对 HTML 标签和样式有特殊限制。
- 网站正文修改时不应覆盖已编辑的公众号版本。

### source 和 source_url

用于记录内容来源。

规则：

- 原创内容可填写 `原创`。
- 转载内容必须记录来源。
- `source_url` 仅在存在外部来源时填写。

## 5.4 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_slug` (`slug`),
KEY `idx_category_status_published` (`category_id`, `status`, `published_at`),
KEY `idx_status_top_published` (`status`, `is_top`, `published_at`),
KEY `idx_status_recommended_sort` (`status`, `is_recommended`, `sort`),
KEY `idx_cover_media_id` (`cover_media_id`),
KEY `idx_wechat_cover_media_id` (`wechat_cover_media_id`),
KEY `idx_deleted_at` (`deleted_at`)
```

说明：

- `slug` 必须唯一。
- 分类和发布时间是前台文章列表高频查询条件。
- 置顶和推荐使用联合索引。
- 不为标题创建普通索引，标题搜索可先使用 `LIKE`，后续再接搜索服务。

## 5.5 建表 SQL 参考

```sql
CREATE TABLE `articles` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `category_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `title` VARCHAR(255) NOT NULL,
    `title_en` VARCHAR(255) NOT NULL DEFAULT '',
    `slug` VARCHAR(180) NOT NULL,
    `cover_media_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `summary` VARCHAR(500) NOT NULL DEFAULT '',
    `content` LONGTEXT NULL,
    `content_format` TINYINT UNSIGNED NOT NULL DEFAULT 1,
    `wechat_content` LONGTEXT NULL,
    `wechat_cover_media_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `wechat_excerpt` VARCHAR(120) NOT NULL DEFAULT '',
    `author` VARCHAR(100) NOT NULL DEFAULT '',
    `source` VARCHAR(100) NOT NULL DEFAULT '',
    `source_url` VARCHAR(500) NOT NULL DEFAULT '',
    `status` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `is_recommended` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `is_top` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `sort` INT UNSIGNED NOT NULL DEFAULT 0,
    `published_at` TIMESTAMP NULL DEFAULT NULL,
    `seo_title` VARCHAR(255) NOT NULL DEFAULT '',
    `seo_description` VARCHAR(500) NOT NULL DEFAULT '',
    `created_at` TIMESTAMP NULL DEFAULT NULL,
    `updated_at` TIMESTAMP NULL DEFAULT NULL,
    `deleted_at` TIMESTAMP NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_slug` (`slug`),
    KEY `idx_category_status_published` (`category_id`, `status`, `published_at`),
    KEY `idx_status_top_published` (`status`, `is_top`, `published_at`),
    KEY `idx_status_recommended_sort` (`status`, `is_recommended`, `sort`),
    KEY `idx_cover_media_id` (`cover_media_id`),
    KEY `idx_wechat_cover_media_id` (`wechat_cover_media_id`),
    KEY `idx_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5.6 业务规则

- `category_id` 必须指向有效分类。
- `slug` 必须唯一。
- 发布状态下必须存在标题、正文和发布时间。
- `published_at` 为空时不能视为正式发布。
- `wechat_excerpt` 最大 120 个字符。
- 网站摘要最大 500 个字符。
- SEO 标题为空时可回退为文章标题。
- 软删除文章时不删除媒体资源。
- 软删除文章时不删除公众号同步记录。
- 恢复文章后保留原同步记录。

| deleted_at | TIMESTAMP | 是 | NULL | 软删除时间 |

## 6.3 视频来源枚举

```text
0 = local
1 = wechat_channels
2 = douyin
3 = kuaishou
4 = bilibili
5 = youtube
6 = other
```

## 6.4 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_slug` (`slug`),
KEY `idx_source_source_video` (`source`, `source_video_id`),
KEY `idx_status_published` (`status`, `published_at`),
KEY `idx_status_recommended_sort` (`status`, `is_recommended`, `sort`),
KEY `idx_cover_media_id` (`cover_media_id`),
KEY `idx_video_media_id` (`video_media_id`),
KEY `idx_deleted_at` (`deleted_at`)
```

说明：

- `source + source_video_id` 不设置唯一索引，因为本地或部分平台可能没有外部 ID。
- 业务层应在外部 ID 非空时避免重复录入。

## 6.5 建表 SQL 参考

```sql
CREATE TABLE `videos` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `title` VARCHAR(255) NOT NULL,
    `title_en` VARCHAR(255) NOT NULL DEFAULT '',
    `slug` VARCHAR(180) NOT NULL,
    `cover_media_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `video_media_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `video_url` VARCHAR(500) NOT NULL DEFAULT '',
    `source` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `source_video_id` VARCHAR(150) NOT NULL DEFAULT '',
    `duration` INT UNSIGNED NOT NULL DEFAULT 0,
    `description` TEXT NULL,
    `transcript` LONGTEXT NULL,
    `status` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `is_recommended` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `sort` INT UNSIGNED NOT NULL DEFAULT 0,
    `published_at` TIMESTAMP NULL DEFAULT NULL,
    `seo_title` VARCHAR(255) NOT NULL DEFAULT '',
    `seo_description` VARCHAR(500) NOT NULL DEFAULT '',
    `created_at` TIMESTAMP NULL DEFAULT NULL,
    `updated_at` TIMESTAMP NULL DEFAULT NULL,
    `deleted_at` TIMESTAMP NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_slug` (`slug`),
    KEY `idx_source_source_video` (`source`, `source_video_id`),
    KEY `idx_status_published` (`status`, `published_at`),
    KEY `idx_status_recommended_sort` (`status`, `is_recommended`, `sort`),
    KEY `idx_cover_media_id` (`cover_media_id`),
    KEY `idx_video_media_id` (`video_media_id`),
    KEY `idx_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6.6 业务规则

- 本地视频优先使用 `video_media_id`。
- 外部视频使用 `video_url` 和 `source_video_id`。
- 本地视频和外部视频至少存在一种有效来源。
- `duration` 统一保存秒数。
- 字幕、脚本和配音文案可统一存入 `transcript`。
- 删除视频时不删除媒体文件。
- 发布状态下必须存在封面和视频来源。

# 八、wechat_articles 微信公众号同步表

## 8.1 表用途

记录网站文章同步到微信公众号后的状态和结果。

## 8.2 字段结构

| 字段 | 类型 | 是否为空 | 默认值 | 说明 |
|---|---|---:|---:|---|
| id | BIGINT UNSIGNED | 否 | 自增 | 主键 |
| article_id | BIGINT UNSIGNED | 否 | 无 | 文章 ID |
| wechat_media_id | VARCHAR(255) | 否 | `''` | 微信素材 ID |
| wechat_article_id | VARCHAR(255) | 否 | `''` | 微信草稿或文章 ID |
| wechat_url | VARCHAR(500) | 否 | `''` | 微信文章地址 |
| sync_status | TINYINT UNSIGNED | 否 | 0 | 同步状态 |
| publish_status | TINYINT UNSIGNED | 否 | 0 | 微信发布状态 |
| error_code | VARCHAR(100) | 否 | `''` | 微信错误码 |
| error_message | VARCHAR(1000) | 否 | `''` | 错误信息 |
| synced_at | TIMESTAMP | 是 | NULL | 最近同步时间 |
| published_at | TIMESTAMP | 是 | NULL | 微信发布时间 |
| created_at | TIMESTAMP | 是 | NULL | 创建时间 |
| updated_at | TIMESTAMP | 是 | NULL | 更新时间 |

## 8.3 同步状态枚举

```text
0 = pending
1 = syncing
2 = success
3 = failed
```

## 8.4 发布状态枚举

```text
0 = unpublished
1 = publishing
2 = published
3 = publish_failed
```

## 8.5 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_article_id` (`article_id`),
KEY `idx_sync_status_updated` (`sync_status`, `updated_at`),
KEY `idx_publish_status_updated` (`publish_status`, `updated_at`),
KEY `idx_wechat_article_id` (`wechat_article_id`)
```

说明：

- 一篇文章最多对应一条同步记录。
- 重复同步时更新原记录，不新增多条。
- V1.0 不保留每次同步历史。

## 8.6 建表 SQL 参考

```sql
CREATE TABLE `wechat_articles` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `article_id` BIGINT UNSIGNED NOT NULL,
    `wechat_media_id` VARCHAR(255) NOT NULL DEFAULT '',
    `wechat_article_id` VARCHAR(255) NOT NULL DEFAULT '',
    `wechat_url` VARCHAR(500) NOT NULL DEFAULT '',
    `sync_status` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `publish_status` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `error_code` VARCHAR(100) NOT NULL DEFAULT '',
    `error_message` VARCHAR(1000) NOT NULL DEFAULT '',
    `synced_at` TIMESTAMP NULL DEFAULT NULL,
    `published_at` TIMESTAMP NULL DEFAULT NULL,
    `created_at` TIMESTAMP NULL DEFAULT NULL,
    `updated_at` TIMESTAMP NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_article_id` (`article_id`),

```

## 8.7 业务规则

- 一篇文章只有一条当前同步状态记录。
- 同步失败必须保留错误码和错误信息。
- 同步成功后清空上一次失败信息。
- 发布成功后记录 `wechat_url` 和 `published_at`。
- 网站文章软删除时不删除同步记录。
- 微信接口密钥不得保存到本表。
- 微信同步操作应通过队列执行。

# 十五、删除策略

## 15.1 文章分类

- 使用软删除。
- 存在子分类时禁止删除。
- 存在未删除文章时禁止删除。
- 恢复分类时不自动恢复子分类。

## 15.2 文章

- 使用软删除。
- 不删除媒体资源。
- 不删除微信公众号同步记录。
- 恢复文章后保留同步状态。
- 恢复前检查分类是否有效。

## 15.3 视频

- 使用软删除。
- 不删除封面和视频媒体。
- 不删除外部平台资源。

## 15.4 专题

- 使用软删除。
- 不删除专题引用的文章、视频、发型或发色。
- 恢复后重新校验引用内容。

## 15.5 微信同步记录

- 不使用软删除。
- 原则上不允许后台删除。
- 必要时通过管理命令或审计流程清理。

# 十六、性能与查询规则

- 文章列表必须预加载分类、封面和微信同步状态。
- 视频列表必须预加载封面和本地视频媒体。
- 列表页禁止加载完整正文、公众号正文和字幕全文。
- 专题列表不加载完整 `config` 和正文。
- 后台分类数量使用 `withCount`。
- 禁止在循环中逐条查询媒体和分类。
- 前台列表查询必须限制返回字段。
- 标题搜索在数据量较小时使用 `LIKE`。
- 内容规模增长后再引入全文索引或搜索服务。
- 微信同步查询按状态和更新时间处理。
- 大文本字段不得进入高频缓存键。

# 二十、设计结论

HairHub V1.0 内容模块采用：

```text
文章分类
+
文章主表
+
视频主表
+
专题主表
+
微信公众号同步表
```

该结构能够满足：

- 网站内容发布
- SEO 内容建设
- 视频教程管理
- 专题运营
- 公众号内容同步
- Dcat Admin 后台运营
- 后续多平台内容扩展

V1.0 优先保证内容资产独立、发布流程清晰、同步状态可追踪，不提前引入复杂内容关系和版本系统。
