# 一、设计目标

## 1.1 后台定位

HairHub V1.0 使用 Dcat Admin 作为后台管理系统。

后台不是简单的数据 CRUD 工具，而是 HairHub 的：

* 内容生产中心
* 发型资产管理中心
* 发色资产管理中心
* AI 任务管理中心
* SEO 运营中心
* 微信公众号内容分发中心
* 系统配置中心

HairHub V1.0 暂不开发用户登录、社区、商城、订单、支付等复杂业务，因此后台设计重点围绕以下核心目标展开：

> 高效管理发型、发色、文章、视频等内容资产，并通过 AI、SEO 和微信生态实现流量获取与内容分发。

---

## 1.2 后台设计原则

后台设计遵循以下原则：

### 1. 简单优先

V1.0 不追求复杂后台功能。

只实现真正影响运营效率的能力。

避免：

* 过度封装
* 复杂工作流
* 多层审批
* 不必要的权限体系
* 为未来假设需求提前开发大量功能

---

### 2. 运营效率优先

后台页面应尽量减少重复操作。

例如新增一个发型时，应能够在同一个表单中完成：

* 基础信息
* 分类选择
* 标签选择
* 适合人群
* 发型属性
* AI Prompt
* 封面上传
* SEO 信息

避免运营人员在多个页面之间反复切换。

---

### 3. 配置优先

能够通过后台配置的内容，不应写死在代码中。

包括：

* 首页推荐内容
* 首页模块顺序
* 热门发型
* 热门发色
* SEO 默认配置
* 微信二维码
* AI Provider 配置
* 系统基础信息

---

### 4. 内容资产优先

HairHub 的长期核心资产包括：

* 发型数据
* 发色数据
* 图片资源
* 文章
* 视频
* 专题

后台首先保证这些内容能够方便地：

* 创建
* 编辑
* 分类
* 搜索
* 筛选
* 发布
* 下架

---

### 5. 保持 Laravel 与 Dcat Admin 原生开发习惯

V1.0 不引入复杂后台框架或额外模块系统。

后台代码遵循现有目录：

```text
app/Admin/

├── Controllers/

├── Forms/

├── Metrics/

├── Actions/

├── Extensions/

└── routes.php
```

业务数据模型继续统一放在：

```text
app/Models/
```

复杂业务逻辑放在：

```text
app/Services/
```

保持项目结构简单、清晰，降低个人开发和后期维护成本。

# 二、后台菜单

## 2.1 整体菜单结构

HairHub V1.0 后台菜单建议设计为：

```text
Dashboard

├── 数据概览


发型中心

├── 发型管理

├── 发型分类

└── 发型标签


发色中心

├── 发色管理

└── 发色分类


内容中心

├── 文章管理

├── 文章分类

├── 视频管理

└── 专题管理


媒体中心

└── 媒体资源


AI中心

├── AI任务

└── AI配置


SEO中心

└── SEO管理


微信公众号

└── 文章同步记录


首页运营

└── 首页模块配置


系统管理

└── 系统配置
```

---

## 2.2 菜单设计原则

一级菜单按照业务领域划分。

不按照数据库表划分。

例如：

不建议：

```text
内容

├── articles

├── article_categories

├── videos

└── topics
```

建议：

```text
内容中心

├── 文章管理

├── 文章分类

├── 视频管理

└── 专题管理
```

后台菜单应该面向运营人员，而不是面向数据库开发人员。

---

## 2.3 V1.0 不显示的菜单

以下模块 V1.0 不进入后台菜单：

* 用户管理
* 会员管理
* 商品管理
* 订单管理
* 支付管理
* 评论管理
* 社区管理
* 发型师管理
* 门店管理

未来真正开发对应功能时再增加。

# 四、发型中心

## 4.1 模块定位

发型中心是 HairHub 最重要的内容资产模块之一。

主要负责：

* 发型分类
* 发型数据
* 发型标签
* 发型图片
* 发型 AI Prompt
* 发型 SEO 信息

一个发型数据未来可以同时服务于：

* 发型图库
* 发型详情页
* AI 换发型
* 首页推荐
* SEO 页面
* 相关文章推荐

因此应避免重复维护相同数据。

---

## 4.2 发型管理列表

菜单路径：

```text
发型中心

└── 发型管理
```

对应数据表：

```text
hairstyles
```

建议列表字段：

| 字段   | 说明         |
| ---- | ---------- |
| ID   | 发型ID       |
| 封面   | 缩略图        |
| 名称   | 发型名称       |
| 分类   | 所属分类       |
| 性别   | 男/女/通用     |
| 脸型   | 适合脸型       |
| 发量   | 适合发量       |
| 打理难度 | 简单/一般/复杂   |
| 状态   | 启用/禁用      |
| 排序   | sort       |
| 更新时间 | updated_at |

---

## 4.3 发型列表筛选

支持：

* 发型名称
* 分类
* 标签
* 性别
* 脸型
* 发量
* 发长
* 状态
* 创建时间

例如：

```text
分类：男生短发

性别：男

脸型：圆脸

发量：少

状态：正常
```

可以快速筛选：

> 适合圆脸、发量少男性的短发。

这对未来内容运营非常有价值。

---

## 4.4 发型新增与编辑

发型表单建议使用 Tab 分组。

```text
基础信息

图片资源

```

---

### Tab 1：基础信息

字段：

```text

英文名称

Slug *

所属分类 *

发型标签

发型描述

状态

```

其中：

* `发型名称` 必填
* `Slug` 可以根据名称自动生成，也允许手动修改
* 标签支持多选

---

### Tab 2：适合人群

字段：

```text
适合性别

适合年龄

适合职业

风格类型

适合脸型

适合发质

适合发量

头发长度

打理难度

```

部分字段允许多选。

例如：

```text
适合脸型：

☑ 圆脸

☑ 方脸

☑ 鹅蛋脸
```

V1.0 数据库字段可以根据最终 Migration 设计采用：

* JSON
* 枚举
* 字符串

具体实现以《04-数据库设计.md》最终字段类型为准。

---

### Tab 3：图片资源

字段：

```text
封面图片 *

更多图片（未来预留）
```

上传封面后：

1. 保存原图
2. 自动生成一个缩略图
3. 创建 `media_files` 记录
4. `hairstyles.cover_media_id` 关联媒体资源

目录建议：

```text
storage/uploads/hairstyle/YYYY/MM/DD/
```

例如：

```text
storage/uploads/hairstyle/2026/07/09/abc123.jpg
```

缩略图：

```text
storage/uploads/hairstyle/2026/07/09/abc123_thumb.jpg
```

列表页面优先显示缩略图。

详情页面显示原图。

---

### Tab 4：AI 配置

字段：

```text
AI Prompt

AI Negative Prompt
```

用途：

AI 换发型时，可以根据选择的发型获取对应 Prompt。

V1.0 当前主要使用 HairFastGAN，但字段保持模型无关。

未来可以支持：

* OpenAI
* Flux
* ComfyUI
* 其他模型

---

### Tab 5：SEO 设置

字段：

```text
SEO Title

SEO Description
```

如果为空：

可以自动使用：

```text
SEO Title = 发型名称 + 默认标题模板
```

例如：

```text
韩系纹理短发适合什么脸型？韩系纹理短发效果图与打理方法 - HairHub
```

SEO Description 可以根据发型描述自动生成默认值。

V1.0 可以先实现简单软删除，复杂关联检查后续完善。

# 六、内容中心

负责：

* 文章
* 文章分类
* 视频
* 专题

内容中心的目标不是单纯发布资讯，而是持续沉淀可被搜索引擎收录的长期内容资产。

* 网站内链不适合直接同步至公众号
* 公众号图片地址可能需要重新处理

建议提供：


复制后允许人工调整。

# Part 1 总结

HairHub Dcat Admin Part 1 主要解决三个问题：

1. 如何高效维护发型和发色核心资产。
2. 如何持续生产文章、视频和专题内容。
3. 如何统一管理大量图片和 AI 生成资源。

其中最核心的后台工作流是：

```text
发型/发色数据录入
        ↓
形成内容资产
        ↓
提供前台图库与AI工具使用
        ↓
生成SEO页面
        ↓
文章和视频持续扩展内容
        ↓
获取自然搜索流量
```

Part 2 将继续定义：

* AI 中心
* SEO 中心
* 微信公众号
* 首页运营与系统设置
* 权限设计

# 十五、总结

HairHub V1.0 Dcat Admin 后台设计围绕三个核心目标：

```text
内容资产管理

+

AI 能力配置与排查

+

SEO 和微信生态运营
```

后台不是为了做复杂系统，而是为了让一个人也能高效维护 HairHub 的核心资产。

V1.0 后台应优先保证：

* 发型数据能快速录入
* 发色数据能快速录入
* 文章和视频能持续发布
* 图片资源能统一管理
* AI 任务能排查问题
* SEO 信息能维护
* 微信公众号内容能同步

最终目标：

> 让 HairHub 可以持续积累内容、持续获取 SEO 流量，并通过 AI 工具和微信生态完成转化。
