> Version: 1.0.0  
> 技术栈：Laravel 10 + Dcat Admin + MySQL 8.0+

# 一、模块目标

AI 任务模块统一记录以下任务：

- AI 换发型
- AI 换发色
- 脸型分析
- 发型推荐
- 图片增强
- 后续新增的 AI 能力

V1.0 负责：

- 创建、排队和执行任务
- 保存输入、输出、模型及请求参数
- 管理任务状态、进度、重试和取消
- 支持幂等、回调和后台排查
- 保留必要的错误信息与执行时间

V1.0 数据表：

```text
ai_tasks
```

本模块不负责会员扣费、订单支付、文件存储、模型密钥和推理服务内部日志。

# 二、数据关系

```text
media_files
   ▲      ▲
   │      │
 input  result
   │      │
   └── ai_tasks ── target_type + target_id
```

- `input_media_id`：输入图片。
- `result_media_id`：生成结果图片。
- `target_type + target_id`：发型、发色或其他业务目标。
- 不创建数据库物理外键。
- AI 任务不使用软删除。

---

# 三、统一约定

- 存储引擎：`InnoDB`
- 字符集：`utf8mb4`
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 状态和类型使用 `TINYINT UNSIGNED`
- PHP 使用 Enum 管理状态值
- 请求参数和结构化结果使用 JSON
- 图片必须通过 `media_files` 管理
- 禁止保存密钥、Token、Cookie、Authorization Header
- 禁止将 Base64 图片写入 JSON
- 所有逻辑关联字段必须建立索引

任务编号建议：

```text
AIT202607110001
```

要求全局唯一，并作为外部接口查询编号，不直接暴露自增 ID。

## 4.2 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_task_no` (`task_no`),
UNIQUE KEY `uk_idempotency_key` (`idempotency_key`),
KEY `idx_type_status_created` (`type`, `status`, `created_at`),
KEY `idx_status_priority_created` (`status`, `priority`, `created_at`),
KEY `idx_input_media_id` (`input_media_id`),
KEY `idx_result_media_id` (`result_media_id`),
KEY `idx_target_type_id` (`target_type`, `target_id`),
KEY `idx_provider_model` (`provider`, `model`),
KEY `idx_request_id` (`request_id`),
KEY `idx_expired_at` (`expired_at`)
```

`idempotency_key` 必须允许 NULL，因为 MySQL 唯一索引允许多条 NULL，但不允许多条空字符串。

# 六、JSON 字段

## 6.1 request_params

示例：

```json
{
  "prompt": "short korean hairstyle",
  "negative_prompt": "blur, deformed",
  "strength": 0.8,
  "seed": 123456,
  "steps": 30,
  "width": 1024,
  "height": 1024
}
```

仅保存模型参数，不保存图片二进制和敏感凭证。

## 6.2 result_data

用于保存结构化结果，例如：

```json
{
  "face_shape": "round",
  "confidence": 0.92,
  "recommendations": [1, 2, 3],
  "execution_time_ms": 8200
}
```

- 图片结果使用 `result_media_id`。
- 分析结果、置信度和执行元数据使用 `result_data`。
- JSON 不作为高频筛选条件。

# 七、状态流转

标准流转：

```text
pending → processing → success
pending → processing → failed
pending → cancelled
processing → cancelled
```

禁止：

```text
success → pending
success → processing
cancelled → processing
```

创建任务：

```text
status = pending
progress = 0
retry_count = 0
started_at = NULL
finished_at = NULL
```

开始执行：

```text
status = processing
started_at = now()
```

成功：

```text
status = success
progress = 100
finished_at = now()
result_media_id > 0 或 result_data 非空
```

失败：

```text
status = failed
finished_at = now()
error_code 非空或 error_message 非空
```

取消：

```text
status = cancelled
finished_at = now()
```

状态变更必须由 Service 统一管理，禁止后台直接修改。

# 八、幂等与并发

## 8.1 创建幂等

创建任务时：

1. Service 生成 `idempotency_key`。
2. 查询是否已有相同任务。
3. 已存在则返回原任务。
4. 不存在则创建。
5. 唯一索引作为最终防重。

幂等键可由以下内容组合并哈希：

```text
用户标识
输入媒体 ID
任务类型
目标类型
目标 ID
关键参数
时间窗口
```

## 8.2 Worker 抢占

任务执行前使用条件更新：

```sql
UPDATE ai_tasks
SET status = 1,
    started_at = NOW()
WHERE id = ?
  AND status = 0;
```

只有受影响行数为 1 时才能继续执行。

同时建议获取 Redis 分布式锁：

```text
ai_task:{task_id}
```

锁必须设置过期时间，执行结束后释放。

## 8.3 回调幂等

异步回调处理：

1. 验证签名。
2. 根据 `request_id` 找任务。
3. 仅 processing 状态接收结果。
4. success 或 cancelled 状态忽略重复回调。
5. 原子保存结果和状态。

# 九、重试策略

适合自动重试：

- 网络超时
- 临时限流
- 模型服务暂时不可用
- 临时存储异常
- 队列执行中断

不适合自动重试：

- 输入图片不合法
- 人脸检测失败
- 参数校验失败
- 目标对象不存在
- 内容安全拒绝
- 用户主动取消

规则：

- 每次真实重试后 `retry_count + 1`。
- 达到 `max_retries` 后设为 failed。
- 使用退避策略重新派发。
- 人工重试必须写后台操作日志。
- V1.0 不建立独立重试历史表。

# 十一、Service 与 Provider

建议结构：

```text
AiTaskService
AiTaskExecutor
AiTaskProviderInterface
```

## 11.1 AiTaskService

负责：

- 创建和查询任务
- 幂等校验
- 取消任务
- 人工重试
- 状态流转
- 保存结果

## 11.2 AiTaskExecutor

负责：

- 抢占任务
- 获取执行锁
- 调用 Provider
- 保存成功结果
- 处理异常和重试
- 释放锁

## 11.3 Provider 接口

```php
interface AiTaskProviderInterface
{
    public function execute(AiTask $task): AiTaskResult;

    public function cancel(AiTask $task): bool;
}
```

实现示例：

```text
HairFastGanProvider
ComfyUiProvider
OpenAiProvider
QwenProvider
```

# 十二、Queue Job

建议：

```text
ExecuteAiTaskJob
RetryAiTaskJob
CleanupExpiredAiTaskJob
```

- `ExecuteAiTaskJob`：执行任务并处理异常。
- `RetryAiTaskJob`：校验错误类型和重试次数后重新派发。
- `CleanupExpiredAiTaskJob`：清理过期临时媒体，不删除任务记录。

任务队列名称保存到 `queue_name`，便于排查和分流。

# 十五、数据保留与清理

- `ai_tasks` 不使用软删除。
- 后台不提供删除功能。
- 历史任务可按时间归档。
- `expired_at` 只控制结果是否可访问，不自动删除任务。
- 临时媒体清理前必须确认没有业务引用。
- 错误信息只保留最近一次，禁止记录敏感凭证。
- V1.0 不保存完整状态和重试历史。

---

# 十六、性能规则

- 状态队列查询使用联合索引。
- Worker 按 `status + priority + created_at` 获取任务。
- JSON 字段不得用于高频筛选。
- 列表查询限制字段。
- 媒体关系必须预加载。
- 不在循环中逐条查询媒体。
- 大量历史数据应归档。
- 不对 `error_message` 做高频模糊搜索。

待处理任务示例：

```sql
SELECT id
FROM ai_tasks
WHERE status = 0
ORDER BY priority DESC, created_at ASC
LIMIT 100;
```

# 十七、监控指标

可基于 `ai_tasks` 统计：

- 每日任务量
- 成功率和失败率
- 各类型任务量
- 各模型和供应商成功率
- 平均排队时间
- 平均执行时间
- 重试次数
- 过期任务数量

计算：

```text
排队时间 = started_at - created_at
执行时间 = finished_at - started_at
```

# 十九、Cursor 开发约束

Cursor 开发本模块时必须：

1. 阅读本文档和 `.cursor/rules`。
2. 检查现有 Migration、Model、Enum、Service、Job、Controller。
3. 不得自行修改字段、类型、默认值和索引。
4. 不创建数据库物理外键。
5. 类型、状态、优先级和目标类型必须使用 PHP Enum。
6. 不保存密钥、敏感 Header 和 Base64 图片。
7. 状态更新必须校验合法流转。
8. Worker 必须使用条件更新和分布式锁防重。
9. 幂等键由 Service 统一生成。
10. 执行逻辑放入 Service、Executor、Provider 和 Job。
11. Dcat Controller 只配置页面并调用 Service。
12. 列表不加载完整 JSON 和错误文本。
13. 任务不使用软删除。
14. 不修改无关模块。
15. 完成后输出文件清单、命令和风险点。

# 二十一、设计结论

HairHub V1.0 AI 任务模块采用：

```text
单一 ai_tasks 核心表
+
Laravel Queue
+
Provider 适配器
+
media_files
```

该结构能够支持换发型、换发色、脸型分析、发型推荐、任务排队、状态追踪、幂等、重试、模型替换和后台排查。

V1.0 优先保证任务可追踪、状态可控、执行防重和模型可替换，不提前引入复杂步骤表、日志表与计费表。
