# HairHub V1.0 图库与资源关联模块 MySQL 表结构详细设计

> Version: 1.0.0  
> 适用项目：HairHub 发型中心  
> 技术栈：Laravel 10 + Dcat Admin + MySQL 8.0+  
> 文档路径：`/docs/v1.0/database/07-图库与资源关联模块.md`

---

# 一、模块目标

图库与资源关联模块用于管理发型、发色与媒体资源之间的一对多关系，解决单一 `cover_media_id` 无法满足多图展示的问题。

V1.0 重点支持：

- 发型详情多图
- 发色详情多图
- 正面、侧面、背面等角度图
- 效果图、示例图、前后对比图
- AI 示例图
- 图片排序
- 图片状态
- 图片标题与 ALT 文本
- 图片 SEO
- Dcat Admin 图库维护
- 前台图库和详情页展示

V1.0 涉及以下数据表：

```text
hairstyle_media
hair_color_media
```

---

# 二、模块边界

本模块负责：

- 维护发型与媒体关系
- 维护发色与媒体关系
- 图片类型
- 图片排序
- 图片标题和 ALT 文本
- 主图和封面标记
- 图片状态
- 前台展示顺序

本模块不负责：

- 文件上传和实际存储
- 图片压缩和缩略图生成
- 文件访问权限
- 媒体去重
- 图片审核
- 图片版权授权
- 视频资源关系

以上能力由：

```text
media_files
MediaService
ThumbnailService
内容安全服务
后续版权模块
```

负责。

# 三、数据关系

```text
hairstyles
    │
    │ 1:N
    ▼
hairstyle_media
    │
    │ N:1
    ▼
media_files


hair_colors
    │
    │ 1:N
    ▼
hair_color_media
    │
    │ N:1
    ▼
media_files
```

关系说明：

- 一个发型可以关联多张媒体图片。
- 一个发色可以关联多张媒体图片。
- 一张媒体图片可被多个业务对象复用。
- `cover_media_id` 继续保留在主表中，作为高频列表封面字段。
- 图库表负责详情页、多角度图和附加图片。
- 不创建数据库物理外键。

# 四、为什么不使用通用 media_relations

V1.0 不采用：

```text
media_relations
```

配合：

```text
model_type
model_id
media_id
```

的通用多态表。

原因：

- 发型和发色业务字段不同。
- Laravel 关系更清晰。
- Dcat Admin 更容易维护。
- 查询和索引更明确。
- Cursor 不容易生成过度抽象代码。
- 后续需要独立扩展时更方便。

因此 V1.0 使用：

```text
hairstyle_media
hair_color_media
```

# 五、统一设计约定

## 5.1 基础规范

- 存储引擎：`InnoDB`
- 字符集：`utf8mb4`
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 不创建数据库物理外键
- 所有逻辑关联字段必须建立索引
- 关联表不使用软删除
- 状态字段使用 `TINYINT UNSIGNED`
- 状态值由 PHP Enum 管理
- 排序字段使用 `INT UNSIGNED`
- 图片标题和 ALT 文本独立保存
- 图片来源和物理文件信息由 `media_files` 负责

## 5.2 排序规则

默认排序：

```text
is_primary DESC, sort DESC, id ASC
```

说明：

- 主图优先。
- sort 越大越靠前。
- id 保证结果稳定。

## 5.3 主图规则

- 每个发型最多一张 `is_primary = 1`。
- 每个发色最多一张 `is_primary = 1`。
- 设置新主图时必须取消其他主图。
- 主表的 `cover_media_id` 应与图库主图保持一致。
- 更新主图必须通过 Service 事务处理。

# 六、hairstyle_media 发型图库关联表

## 6.1 表用途

维护发型与媒体图片之间的关系。

支持：

- 封面图
- 正面图
- 侧面图
- 背面图
- 细节图
- AI 示例图
- 前后对比图
- 其他展示图

## 6.2 字段结构

| 字段 | 类型 | 是否为空 | 默认值 | 说明 |
|---|---|---:|---:|---|
| id | BIGINT UNSIGNED | 否 | 自增 | 主键 |
| hairstyle_id | BIGINT UNSIGNED | 否 | 无 | 发型 ID |
| media_id | BIGINT UNSIGNED | 否 | 无 | 媒体 ID |
| type | TINYINT UNSIGNED | 否 | 0 | 图片类型 |
| title | VARCHAR(255) | 否 | `''` | 图片标题 |
| alt_text | VARCHAR(255) | 否 | `''` | 图片 ALT 文本 |
| caption | VARCHAR(500) | 否 | `''` | 图片说明 |
| is_primary | TINYINT UNSIGNED | 否 | 0 | 是否主图 |
| status | TINYINT UNSIGNED | 否 | 1 | 状态 |
| sort | INT UNSIGNED | 否 | 0 | 排序值 |
| created_at | TIMESTAMP | 是 | NULL | 创建时间 |
| updated_at | TIMESTAMP | 是 | NULL | 更新时间 |

## 6.3 图片类型枚举

建议：

```text
0 = gallery
1 = cover
2 = front
3 = side
4 = back
5 = detail
6 = before
7 = after
8 = ai_example
9 = inspiration
```

说明：

- `gallery`：普通图库图。
- `cover`：封面图。
- `front`：正面图。
- `side`：侧面图。
- `back`：背面图。
- `detail`：细节图。
- `before`：处理前。
- `after`：处理后。
- `ai_example`：AI 换发型示例。
- `inspiration`：灵感参考图。

## 6.4 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_hairstyle_media` (`hairstyle_id`, `media_id`),
KEY `idx_hairstyle_status_sort` (`hairstyle_id`, `status`, `sort`),
KEY `idx_hairstyle_primary` (`hairstyle_id`, `is_primary`),
KEY `idx_media_id` (`media_id`),
KEY `idx_type_status` (`type`, `status`)
```

说明：

- 同一发型不能重复关联同一媒体。
- 按发型查询图库使用联合索引。
- 主图查询使用 `hairstyle_id + is_primary`。
- `media_id` 用于反向检查引用。

## 6.5 建表 SQL 参考

```sql
CREATE TABLE `hairstyle_media` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `hairstyle_id` BIGINT UNSIGNED NOT NULL,
    `media_id` BIGINT UNSIGNED NOT NULL,
    `type` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `title` VARCHAR(255) NOT NULL DEFAULT '',
    `alt_text` VARCHAR(255) NOT NULL DEFAULT '',
    `caption` VARCHAR(500) NOT NULL DEFAULT '',
    `is_primary` TINYINT UNSIGNED NOT NULL DEFAULT 0,
    `status` TINYINT UNSIGNED NOT NULL DEFAULT 1,
    `sort` INT UNSIGNED NOT NULL DEFAULT 0,
    `created_at` TIMESTAMP NULL DEFAULT NULL,
    `updated_at` TIMESTAMP NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_hairstyle_media` (`hairstyle_id`, `media_id`),
    KEY `idx_hairstyle_status_sort` (`hairstyle_id`, `status`, `sort`),
    KEY `idx_hairstyle_primary` (`hairstyle_id`, `is_primary`),
    KEY `idx_media_id` (`media_id`),
    KEY `idx_type_status` (`type`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6.6 业务规则

- `hairstyle_id` 必须指向有效发型。
- `media_id` 必须指向有效图片媒体。
- 仅允许关联 `file_type = image` 的媒体。
- 每个发型最多一张主图。
- 设置主图时同步更新 `hairstyles.cover_media_id`。
- 删除主图关联时必须指定新的主图或清空封面。
- 禁用图片后前台不展示。
- 删除发型时物理删除其图库关联记录。
- 删除关联不删除媒体文件。

# 八、主图一致性策略

## 8.1 保留 cover_media_id 的原因

主表继续保留：

```text
hairstyles.cover_media_id
hair_colors.cover_media_id
```

原因：

- 列表查询更快。
- 首页卡片无需 JOIN 图库表。
- Dcat Grid 展示简单。
- SEO 和分享场景读取方便。

图库表中的 `is_primary` 用于：

- 维护详情图库顺序。
- 标识主图关系。
- 保证后台操作一致性。

## 8.2 更新主图流程

设置发型主图：

```text
开启事务
↓
取消该发型其他 is_primary
↓
设置当前关联 is_primary = 1
↓
更新 hairstyles.cover_media_id
↓
提交事务
```

发色同理。

## 8.3 一致性修复

建议提供命令：

```text
php artisan hairhub:sync-primary-media
```

用于：

- 检查主表封面与图库主图是否一致。
- 自动修复可确定的问题。
- 输出异常记录。

要求：

- 描述图片内容。
- 与发型或发色主题相关。
- 避免关键词堆砌。

示例：


## 9.2 title

用于：

- 后台识别
- 图片标题
- 图库说明
- 分享文案辅助

## 9.3 caption

用于：

- 详情页图片说明
- 角度说明
- 光线说明
- 效果说明

## 9.4 SEO 回退逻辑

```text
alt_text
↓

↓
业务名称 + 图片类型
```

# 十六、删除策略

## 16.1 删除发型或发色

- 主业务对象软删除。
- 图库关联记录可保留或物理删除。
- V1.0 推荐物理删除关联记录。
- 媒体文件不自动删除。
- 孤立媒体由清理任务后续处理。

## 16.2 删除图库关联

- 只删除关联表记录。
- 不删除 `media_files`。
- 删除主图前必须先设置替代主图或清空封面。
- 删除后同步主表 `cover_media_id`。

## 16.3 删除媒体文件

MediaCleanupService 删除媒体前必须检查：

```text
hairstyle_media
hair_color_media
hairstyles.cover_media_id
hair_colors.cover_media_id
其他业务表引用
```

存在任一引用时禁止删除。

# 十九、性能规则

- 详情页一次性预加载图库媒体。
- 列表页继续使用主表 `cover_media_id`。
- 不在列表页 JOIN 全部图库。
- 图片排序使用联合索引。
- 媒体引用检查使用 `media_id` 索引。
- 批量排序使用事务和批量更新。
- 前台只查询启用图片。
- 不加载无关媒体元数据大字段。
- 图库数量较多时分页或限制数量。

---

# 二十、安全与内容规范

- 只允许关联图片类型媒体。
- private 图片不得用于公开图库。
- AI 输入原图不得误设为公开图库图。
- 图片 ALT 和 caption 输出时必须转义。
- 富文本 caption 不在 V1.0 支持。
- 后台设置公开图片前必须检查媒体可见性。
- 涉及人物肖像的素材应确保授权和合规。

# 二十二、Cursor 开发约束

Cursor 开发本模块时必须：

1. 阅读本文档和 `.cursor/rules`。
2. 检查现有 Migration、Model、Enum、Service、Controller。
3. 不得自行修改字段、类型、默认值和索引。
4. 不创建数据库物理外键。
5. 不使用通用多态 media_relations 替代本模块两张表。
6. 每个业务对象最多一个主图。
7. 设置主图必须使用事务。
8. 主图变更必须同步主表 cover_media_id。
9. 只允许关联图片类型媒体。
10. 删除关联不得删除媒体文件。
11. Dcat Controller 只配置页面并调用 Service。
12. 列表和详情查询必须避免 N+1。
13. 关联表不使用软删除。
14. 不修改无关模块。
15. 完成后输出文件清单、命令和风险点。

# 二十四、设计结论

HairHub V1.0 图库与资源关联模块采用：

```text
hairstyle_media
+
hair_color_media
+
media_files
```

该结构能够满足：

- 发型多图展示
- 发色多图展示
- 多角度图片
- 色卡和光线效果图
- AI 示例图
- 图片 SEO
- Dcat Admin 图库维护
- 主图快速读取
- 媒体复用和安全删除

V1.0 优先保证业务关系清晰、查询稳定、后台易维护和图片 SEO 可控，不提前引入通用多态关联表和复杂图库系统。
