# 一、开发目标

HairHub V1.0 的核心开发目标是：

> 以最小可行版本快速上线，通过 AI 换发型、AI 换发色吸引用户，通过发型、发色、文章、视频等内容持续积累 SEO 流量，并将用户导入微信公众号、微信小程序和微信小店。

V1.0 不追求一次性完成所有未来功能。

开发重点围绕：

```text
基础架构

↓

数据库

↓

Dcat Admin 后台

↓

内容资产

↓

前台页面

↓

AI工具

↓

SEO

↓

微信公众号

↓

部署上线
```

# 三、开发总体阶段

HairHub V1.0 建议拆分为 10 个开发阶段：

```text
Phase 0    项目准备与文档确认

Phase 1    数据库与基础架构

Phase 2    Media资源模块

Phase 3    发型中心与发色中心

Phase 4    内容中心

Phase 5    前台基础页面

Phase 6    AI工具

Phase 7    SEO

Phase 8    微信公众号与运营配置

Phase 9    测试、优化与部署上线
```

原则：

> 先完成基础数据能力，再完成前台展示，然后接入 AI、SEO 和微信生态。

---

## 5.5 Service 目录

建立：

```text
app/Services/

├── AI/

├── Hairstyle/

├── HairColor/

├── Content/

├── Media/

├── SEO/

├── Wechat/

└── System/
```

V1.0 不要求每个目录立即创建大量 Service。

只在真正存在业务逻辑时创建。

避免：

```text
一个简单查询

↓

Controller

↓

Service

↓

Repository

↓

Model
```

为了分层而分层。

简单 CRUD 可以直接使用 Eloquent。

复杂业务逻辑进入 Service。

---

## 5.6 Repository 原则

V1.0 不强制所有 Model 创建 Repository。

只有出现以下情况时再引入：

* 查询逻辑复杂
* 多个 Service 复用查询
* 数据源可能变化
* 查询代码大量重复

原则：

> 不为了架构形式增加无意义代码。

---

## 5.7 API 路由

建立版本路由：

```text

```

建议目录：

```text

```

例如：

```text

```

## 5.8 统一 API Response

实现统一响应：

```json
    "message": "success",
    "data": {}
}
```

错误：

```json

    "message": "Data not found",
    "data": null
}
```

```text

```

```text

```

---

## 10.3 HairFastGAN Provider

建议创建：

```text
app/Services/AI/Providers/HairFastGanProvider.php
```

职责：

```text
封装API地址

构造请求参数

发送请求

处理响应

处理超时

转换统一结果格式
```

不要把 HairFastGAN 的 API 请求直接写在 Controller 中。

---

## 10.4 AI 换发型流程

```text
用户上传照片

↓

MediaService保存图片

↓

创建ai_tasks记录

↓

读取目标发型

↓

AiService调用HairFastGAN Provider

↓

独立4090D服务器执行推理

↓

返回生成结果

↓

保存AI结果图片

↓

更新ai_tasks

↓

前端展示结果
```

---

## 10.5 AI 换发色流程

```text
用户上传照片

↓

选择发色

↓

创建任务

↓

调用AI Provider

↓

生成结果

↓

保存结果

↓

返回前端
```

具体是否由 HairFastGAN 实现换发色，以当前实际 API 能力为准。

如果换发色由其他 Provider 提供，不影响整体接口结构。

# 十五、Git 提交建议

每完成一个独立任务提交一次。

例如：

```text
feat: create hairstyle database schema

feat: add hairstyle admin management

feat: add hairstyle api

feat: add media upload service

feat: integrate hairfastgan provider

feat: add article management

feat: add wechat article sync

feat: add sitemap generation

fix: handle ai task timeout
```

避免：

```text
update code

fix bug

modify
```

这种无法表达具体修改内容的提交信息。

# 十六、Cursor 开发使用方式

## 16.1 开发前让 Cursor 阅读文档

不要直接输入：

```text
帮我开发发型模块
```

推荐：

```text
请先阅读：

docs/v1.0/01-项目定位.md
docs/v1.0/02-系统架构.md
docs/v1.0/03-模块设计.md
docs/v1.0/04-数据库设计.md
docs/v1.0/05-API设计规范.md
docs/v1.0/06-Dcat后台设计.md
docs/v1.0/07-前端页面设计.md
docs/v1.0/08-开发任务拆解.md
docs/v1.0/11-开发规范.md

然后实现 Phase 3 中的「发型分类管理」。

要求：

1. 先分析现有项目代码和Dcat Admin目录结构。
2. 不修改无关代码。
3. 遵循Laravel现有目录结构。
4. 不引入新的复杂架构。
5. 完成后列出修改文件。
6. 说明数据库变化。
7. 提供测试方法。
```

---

## 16.2 每次只开发一个明确任务

推荐：

```text
开发 hairstyle_categories Migration
```

完成后：

```text
开发 HairstyleCategory Model
```

然后：

```text
开发 Dcat Admin 发型分类管理
```

而不是一次要求：

```text
把整个HairHub全部开发完成
```

---

## 16.3 Cursor 修改代码前的原则

建议要求 Cursor：

```text
先阅读

↓

先分析

↓

列出计划

↓

再修改代码
```

对于数据库、架构、公共 Service 等重要修改尤其如此。

# 十九、总结

HairHub V1.0 的开发原则是：

> 先上线，再积累，再根据真实数据迭代。

V1.0 不追求功能数量，而追求完整闭环：

```text
AI工具吸引用户

↓

发型与发色内容承接需求

↓

文章和视频形成SEO资产

↓

搜索引擎持续带来流量

↓

微信生态完成用户沉淀和商业转化
```

对于单人开发，最重要的不是同时完成所有功能，而是：

```text
明确任务

↓

小步开发

↓

及时测试

↓

Git提交

↓

持续上线
```

最终目标：

> 用一套简单、稳定、可持续维护的系统，让 HairHub 尽快上线并开始真正积累发型数据、内容资产、SEO权重和用户流量。
