# HairHub V1.0 发色模块 MySQL 表结构详细设计

> Version: 1.0.0  
> 适用项目：HairHub 发型中心  
> 技术栈：Laravel 10 + Dcat Admin + MySQL 8.0+  
> 文档路径：`/docs/v1.0/database/02-发色模块.md`

---

# 一、模块目标

发色模块用于管理 HairHub 的核心发色资产，包括：

- 发色分类
- 发色色卡
- 发色适用肤色
- 发色冷暖属性
- 发色明暗属性
- 发色封面及展示信息
- AI 换发色提示词
- SEO 基础信息

V1.0 涉及以下数据表：

```text
hair_color_categories
hair_colors
```

---

# 二、数据关系

```text
hair_color_categories
        │
        │ 1:N
        ▼
    hair_colors
```

关系说明：

- 一个发色分类可以包含多个发色。
- 一个发色只能归属一个主分类。
- 分类支持一级和二级结构。
- 发色图片通过 `media_files` 逻辑关联。
- 不创建数据库物理外键。

---

# 三、统一设计约定

## 3.1 基础规范

- 存储引擎：`InnoDB`
- 字符集：`utf8mb4`
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 不创建数据库物理外键
- 所有逻辑关联字段必须建立索引
- 状态字段使用 `TINYINT UNSIGNED`
- 状态值由 PHP Enum 统一管理
- 分类表和发色主表使用软删除
- AI Prompt 与前台展示文案分开保存

## 3.2 排序规则

后台和前台默认排序：

```text
sort DESC, id DESC
```

说明：

- `sort` 越大，展示优先级越高。
- `id` 保证相同排序值下结果稳定。

## 3.3 通用状态

```text
0 = disabled
1 = enabled
```

建议使用统一 PHP Enum：

```php
enum CommonStatus: int
{
    case Disabled = 0;
    case Enabled = 1;
}
```

# 四、hair_color_categories 发色分类表

## 4.1 表用途

管理发色分类，支持一级和二级分类。

示例：

```text
自然色系
├── 黑色系
├── 棕色系
└── 亚麻色系

浅色系
├── 金色系
├── 灰色系
└── 白金色系

个性色系
├── 红色系
├── 紫色系
├── 蓝色系
└── 粉色系
```

V1.0 建议最多支持两级分类，数据库结构保留继续扩展能力。

## 4.2 字段结构

| 字段 | 类型 | 是否为空 | 默认值 | 说明 |
|---|---|---:|---:|---|
| id | BIGINT UNSIGNED | 否 | 自增 | 主键 |
| parent_id | BIGINT UNSIGNED | 否 | 0 | 父分类 ID，0 表示顶级分类 |
| name | VARCHAR(100) | 否 | 无 | 分类名称 |
| name_en | VARCHAR(150) | 否 | `''` | 英文名称预留 |
| slug | VARCHAR(150) | 否 | 无 | SEO URL 标识 |
| description | VARCHAR(500) | 是 | NULL | 分类简介 |
| cover_media_id | BIGINT UNSIGNED | 否 | 0 | 分类封面媒体 ID |
| status | TINYINT UNSIGNED | 否 | 1 | 状态 |
| sort | INT UNSIGNED | 否 | 0 | 排序值 |
| created_at | TIMESTAMP | 是 | NULL | 创建时间 |
| updated_at | TIMESTAMP | 是 | NULL | 更新时间 |
| deleted_at | TIMESTAMP | 是 | NULL | 软删除时间 |

## 4.3 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_slug` (`slug`),
KEY `idx_parent_status_sort` (`parent_id`, `status`, `sort`),
KEY `idx_cover_media_id` (`cover_media_id`),
KEY `idx_deleted_at` (`deleted_at`)
```

说明：

- `slug` 必须唯一。
- `parent_id + status + sort` 用于分类树和列表查询。
- `cover_media_id` 为媒体逻辑关联字段。
- 分类采用软删除。

## 4.4 建表 SQL 参考

```sql
CREATE TABLE `hair_color_categories` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `parent_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `name` VARCHAR(100) NOT NULL,
    `name_en` VARCHAR(150) NOT NULL DEFAULT '',
    `slug` VARCHAR(150) NOT NULL,
    `description` VARCHAR(500) NULL,
    `cover_media_id` BIGINT UNSIGNED NOT NULL DEFAULT 0,
    `status` TINYINT UNSIGNED NOT NULL DEFAULT 1,
    `sort` INT UNSIGNED NOT NULL DEFAULT 0,
    `created_at` TIMESTAMP NULL DEFAULT NULL,
    `updated_at` TIMESTAMP NULL DEFAULT NULL,
    `deleted_at` TIMESTAMP NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_slug` (`slug`),
    KEY `idx_parent_status_sort` (`parent_id`, `status`, `sort`),
    KEY `idx_cover_media_id` (`cover_media_id`),
    KEY `idx_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 4.5 业务规则

- 顶级分类的 `parent_id = 0`。
- 不允许父级分类指向自身。
- V1.0 不允许超过两级分类。
- 已被发色使用的分类不得直接物理删除。
- 删除分类前必须检查子分类和发色引用。
- `slug` 仅允许小写字母、数字和短横线。
- 分类名称可以重复，`slug` 不允许重复。

- 发色图库展示

| status | TINYINT UNSIGNED | 否 | 1 | 状态 |
| is_recommended | TINYINT UNSIGNED | 否 | 0 | 是否推荐 |
| sort | INT UNSIGNED | 否 | 0 | 排序值 |
| published_at | TIMESTAMP | 是 | NULL | 发布时间 |
| created_at | TIMESTAMP | 是 | NULL | 创建时间 |
| updated_at | TIMESTAMP | 是 | NULL | 更新时间 |
| deleted_at | TIMESTAMP | 是 | NULL | 软删除时间 |

## 5.3 字段说明

### color_hex

保存标准十六进制颜色值，例如：

```text
#2B1B17
#6F4E37
#C8A27A
#D8B4A0
```

规则：

- 必须以 `#` 开头。
- 支持 7 位 `#RRGGBB`。
- 预留 9 位 `#RRGGBBAA`。
- 仅用于前端色卡展示，不代表真实染发效果。
- 不建议对该字段建立索引。

### suitable_skin

V1.0 使用逗号分隔的英文枚举值，例如：

```text
fair,light
light,medium
medium,tan
all
```

原因：

- V1 数据规模有限。
- 主要用于展示和轻量筛选。
- 可避免增加发色肤色关联表。
- 后续需要复杂推荐时可迁移为关系表。

约束：

- 只能保存系统定义的枚举值。
- 不保存中文展示名称。
- Laravel Model 通过 Accessor 或 Cast 转换为数组。
- 禁止依赖大量 `%LIKE%` 完成复杂推荐。

## 5.4 索引设计

```sql
PRIMARY KEY (`id`),
UNIQUE KEY `uk_slug` (`slug`),
KEY `idx_category_status_sort` (`category_id`, `status`, `sort`),
KEY `idx_temperature_status_sort` (`temperature`, `status`, `sort`),

KEY `idx_recommended_status_sort` (`is_recommended`, `status`, `sort`),
KEY `idx_cover_media_id` (`cover_media_id`),
KEY `idx_published_at` (`published_at`),

```

说明：

- `slug` 必须唯一。
- 分类、冷暖、明暗、推荐状态为高频筛选条件。
- 不为所有枚举字段机械添加索引。
- `suitable_skin` 不建立索引。
- `color_hex` 不建立索引。

# 六、发色枚举建议

## 6.1 brightness 明暗程度

```text
0 = unknown
1 = dark
2 = medium
3 = light
4 = very_light
```

建议 PHP Enum：

```php
enum HairColorBrightness: int
{
    case Unknown = 0;
    case Dark = 1;
    case Medium = 2;
    case Light = 3;
    case VeryLight = 4;
}
```

## 6.2 temperature 冷暖属性

```text
0 = neutral
1 = warm
2 = cool
```

建议 PHP Enum：

```php
enum HairColorTemperature: int
{
    case Neutral = 0;
    case Warm = 1;
    case Cool = 2;
}
```

## 6.3 saturation 饱和度

```text
0 = unknown
1 = low
2 = medium
3 = high
```

## 6.4 bleach_required 是否需要漂发

```text
0 = no
1 = yes
2 = depends
```

说明：

- `no`：通常不需要漂。
- `yes`：通常需要漂。
- `depends`：取决于原始发色和目标效果。

## 6.5 maintenance_level 维护难度

```text
0 = unknown
1 = easy
2 = normal
3 = difficult
```

## 6.6 is_recommended 是否推荐

```text
0 = no
1 = yes
```

## 6.7 suitable_skin 肤色枚举

```text
all
fair
light
medium
tan
deep
warm_skin
cool_skin
neutral_skin
```

说明：

- `fair`：非常白皙。
- `light`：偏白。
- `medium`：自然中等肤色。
- `tan`：健康、小麦色。
- `deep`：深肤色。
- `warm_skin`、`cool_skin`、`neutral_skin` 表示肤色底调。

V1.0 可以同时保存肤色深浅和底调，例如：

```text
light,warm_skin
medium,neutral_skin
tan,cool_skin
```

`suitable_skin` 建议通过 Accessor 和 Mutator 处理：

```php
public function getSuitableSkinAttribute($value): array
{
    return $value === '' ? [] : explode(',', $value);
}

public function setSuitableSkinAttribute(array|string|null $value): void
{
    $items = is_array($value) ? $value : explode(',', (string) $value);

    $items = array_values(array_unique(array_filter(array_map(
        static fn ($item) => trim((string) $item),
        $items
    ))));

    $this->attributes['suitable_skin'] = implode(',', $items);
}
```

要求：

- 保存前去重。
- 保存前去除空值。
- 仅允许保存系统定义的枚举值。
- 业务校验应在 Form Request 或 Service 中完成。

# 十、业务规则

## 10.1 发色分类

- 分类名称允许重复。
- `slug` 必须唯一。
- 分类最多两级。
- 删除前必须检查子分类和发色引用。
- 删除采用软删除。
- 恢复分类时不自动恢复子分类。

## 10.2 发色

- `category_id` 必须指向有效分类。
- 发色名称允许重复，`slug` 必须唯一。
- `color_hex` 必须符合标准格式。
- 上架状态下建议存在有效封面。
- `published_at` 为空时视为未正式发布。
- AI Prompt 不直接展示给前台用户。
- 删除发色只执行软删除。
- 删除发色时不删除封面媒体。
- SEO 标题为空时可回退为发色名称。

## 10.3 推荐规则

`is_recommended = 1` 仅代表运营推荐，不代表算法推荐结果。

前台推荐查询示例：

```sql
WHERE status = 1
  AND is_recommended = 1
  AND deleted_at IS NULL
ORDER BY sort DESC, id DESC
```

# 十三、事务要求

以下操作建议使用数据库事务：

- 新增发色并保存关联媒体信息
- 编辑发色并更新多个业务字段
- 批量移动发色分类
- 批量修改发色状态
- 批量设置推荐状态
- 删除分类并执行引用检查

示例：

```php
DB::transaction(function () use ($data) {
    HairColor::create($data);
});
```

简单单表写入可以不强制使用事务，但涉及多个模型或附属记录时必须使用。

# 十四、删除策略

## 14.1 发色分类

- 使用软删除。
- 存在子分类时禁止删除。
- 存在未删除发色时禁止删除。
- 不自动删除发色。
- 恢复分类时不自动恢复子分类。

## 14.2 发色

- 使用软删除。
- 不删除关联媒体文件。
- 不删除 AI 任务历史。
- 恢复后保留原始分类关系。
- 恢复前必须检查分类是否仍有效。

# 十五、性能与查询规则

- 发色列表必须预加载分类和封面媒体。
- 列表页禁止读取完整正文和 AI Prompt。
- 前台列表查询应限制返回字段。
- 后台批量操作应分批执行。
- 禁止在循环中逐条查询分类和媒体。
- `suitable_skin` 仅用于轻量筛选，不用于复杂推荐 SQL。
- 复杂肤色推荐应在后续版本迁移为独立关系表或推荐索引表。
- 分类统计数量使用 `withCount` 或聚合查询。

前台列表推荐查询字段示例：

```text
id
category_id
name
slug
color_hex
brightness
temperature
cover_media_id
is_recommended
sort
published_at
```

# 十七、Cursor 开发约束

Cursor 开发本模块时必须：

1. 阅读本文档及项目 `.cursor/rules`。
2. 检查是否已有同名 Migration、Model、Enum、Service、Controller。
3. 不得自行修改字段名、字段类型、默认值和索引。
4. 不创建数据库物理外键。
5. 状态、明暗、冷暖、饱和度等字段必须使用 PHP Enum。
6. 业务逻辑不得写入 Dcat Controller。
7. 分类删除检查、字段标准化等逻辑放入 Service。
8. `color_hex` 保存前必须标准化。
9. `suitable_skin` 保存前必须校验、去重并清理空值。
10. 生成 Migration、Model、Enum、Service、Dcat Admin 页面和 Seeder。
11. 不修改无关模块。
12. 完成后输出文件清单、执行命令和风险点。

# 十九、设计结论

HairHub V1.0 发色模块采用：

```text
发色分类表
+
发色主表
```

该结构能够满足：

- 发色资产管理
- 发色分类展示
- 色卡展示
- 冷暖和明暗筛选
- AI 换发色目标选择
- SEO 页面建设
- Dcat Admin 后台运营
- 后续肤色推荐扩展

V1.0 优先保证结构清晰、查询稳定和开发效率，不引入过多关联表和专业染发业务结构。
